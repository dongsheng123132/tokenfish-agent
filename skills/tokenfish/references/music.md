# 音乐生成

调用工具：`tokenfish.music.generate`（计费）。参数：

| 参数 | 说明 |
|---|---|
| `prompt` | 风格描述，必填，≤1000 字符。即使有歌词也要填：描述曲风、情绪、参考风格。 |
| `lyrics` | 歌词，可选，≤5000 字符。`instrumental=true` 时不能填。 |
| `title` | 标题，可选，≤80 字符。 |
| `instrumental` | 是否纯伴奏（无人声），布尔值。 |
| `model` | `auto`（默认，推荐）/ `suno` / `minimax`。不确定就用 `auto`。 |
| `duration` | 可选，1..300 秒。只在用户明确要求时长时才传；不传就让上游给默认时长。 |
| `client_request_id` | 必填，制作卡确认后再生成，同一张卡只用一个值。 |

## 已有歌词（对应「歌词成曲」流程）

1. 先把用户提供的歌词整理成段落（加 `[Verse]` / `[Chorus]` / `[Bridge]` 标签），**默认不改一个字**。只有用户明确说"帮我改一下/优化一下歌词"时，才可以在征得同意后调整措辞——改完要把改动前后都给用户看一遍。
2. 用整理后的歌词和用户描述的风格，出一张制作卡：完整歌词（含段落标签）、标题、风格描述、`model`（默认 auto）、"下一步会扣费"。
3. 用户确认后，生成 `client_request_id`，调用 `tokenfish.music.generate`（`lyrics` 填整理后的歌词）。
4. 结果如果不是终态（`status` 为 `queued`/`running`），用 `tokenfish.tasks.get` 轮询直到 `succeeded` 或 `failed`；轮询间隔给用户一个大概等待的心理预期（上游生成一般要 1-2 分钟到几分钟不等），不要死循环刷屏。
5. 交付：按 `clips` 顺序列出每首的 `play_url`（作品页，可在线试听和下载）、`audio_url`、`duration_seconds`；并**原样**给出 `links.site`、`charged_cny`（没有就说"以钱包流水为准"）、`balance_after_cny` 和 `topup_hint`（有就原样给）。`play_url` 是临时链接，约 24 小时内有效，提醒用户及时下载。

## 纯音乐 / 配乐（最短路径）

用户只要背景音乐、伴奏、纯音乐时：不问歌词，`instrumental` 设为 `true`，`lyrics` 留空，直接根据用户描述的风格/用途生成 `prompt`，走同样的"制作卡 → 确认 → 提交一次"流程。

## 模型选择

`model` 默认 `auto`：客户端会自动路由，不需要用户操心具体用哪个上游。除非用户明确指定要"更稳"或"更快"等偏好，否则不要主动问用户选 `suno` 还是 `minimax`。

### 上游说明（内部参考，不对外使用这些名字）

`auto` 模式的路由顺序是 Suno → MiniMax：先尝试 Suno（异步出稿，性价比更高），提交失败且不是余额问题时才自动切换到 MiniMax（同步出稿，稍慢，请求超时给到 240 秒）。这两个名字**只用于你理解内部机制**，禁止出现在与用户对话的措辞里、也不能写进任何标题或摘要——对用户统一说"音乐模型由上游提供，默认先用效果最好的那个"。
