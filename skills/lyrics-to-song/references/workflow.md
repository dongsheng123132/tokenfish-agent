# 详细流程与示例

## 保留原词模式（默认）

输入（用户给的原始歌词）：

```
你的眼睛像星星
在黑夜里最亮
```

整理后（只加标签，一字不改）：

```
[Verse]
你的眼睛像星星
在黑夜里最亮
```

如果歌词已经写得很长、有明显的段落感（主歌/副歌/桥段），按内容自然断句加标签；如果分不清也没关系，整段放进 `[Verse]` 里，不要为了凑标签而调整措辞。

## 优化歌词模式（需要用户明确授权）

用户说"帮我改一下歌词，押韵差一点"这类话之后：

1. 先展示你打算怎么改（逐句对照原文 → 改后），不要直接替换。
2. 用户确认后，再把改后的版本放进制作卡。
3. 如果用户中途改主意想恢复原词，直接切回保留模式。

## 制作卡格式示例

```
【制作卡】
标题：夜色未眠
风格：City Pop，怀旧合成器音色，中速
歌词：
[Verse]
你的眼睛像星星
在黑夜里最亮
[Chorus]
...
模型：auto（由系统自动选择上游）
下一步会扣费，确认要提交吗？
```

用户回复"提交"/"可以"/"确认"等明确同意后，才生成 `client_request_id` 并调用一次 `tokenfish.music.generate`。如果用户还在改歌词或风格，说明还没到出卡的时候，继续免费沟通。

### 上游说明（内部参考，不对外使用这些名字）

`model=auto` 时客户端会先尝试 Suno 出稿，提交失败且不是余额问题才会自动切换到 MiniMax。这是内部路由细节，帮助你理解"为什么有时候会稍微慢一点"，但对用户只需要说"音乐模型由上游提供，默认先用效果最好的那个"，不要在对话、标题或摘要里出现这两个名字。
